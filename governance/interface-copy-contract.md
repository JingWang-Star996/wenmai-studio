# 文脉界面表达合同

版本：`1.0.0`

日期：`2026-08-27`

经验来源：内部界面文案复盘与 `edit-natural-chinese` 中文自然度门禁；公开合同不携带历史会话标识。

## 1. 目标

文脉的界面文字先帮助用户继续工作，再解释系统怎样实现。每个页面、状态、空白结果和错误提示都应尽量回答四个问题：

1. 我现在在处理什么对象？
2. 我可以采取哪一步动作？
3. 动作完成后，哪个对象会发生什么变化？
4. 当前文字依据哪一层证据，不能推出什么？

这不是“短句化”或禁词替换。保留必要的产品对象、状态、证据边界和不确定性；先恢复主体、动作、对象与可见结果，再重写句子。

## 2. 文本分层

### 用户可见界面

标题、导语、按钮、状态、空状态、错误、恢复提示、表单说明和无障碍名称直接面向操作者。优先使用用户正在处理的对象和动作，不用“系统已实现……”“本页面提供……”作为默认开头。

### Agent 与 API 说明

可以重排信息顺序、补足禁止动作和恢复方法，但不能改动 JSON key、错误码、HTTP 状态、scope、schema、哈希、CAS 条件或输出合同。Agent 只能返回候选、回执或技术结果时，文字不得暗示它拥有批准、合并、发布或最终完成权。

### 机器状态与证据 Claim

机器枚举保持原样。界面可以给出中文名称，但必须显式映射，不能靠全局字符串替换制造“同义状态”。当前发布证据映射为：

| 内部状态 | 界面名称 | 对外 Claim | 只能证明 |
| --- | --- | --- | --- |
| `submission_accepted` | 平台已接受提交 | `submission_accepted` | 平台明确接受了这次提交 |
| `backend_verified` | 后台记录已核验 | `destination_record_verified` | 作者后台存在同一目标记录 |
| `public_verified` | 公开页面已核验 | `public_access_verified` | 独立访问者能打开同一公开对象 |
| 指标记录及复盘结论 | 效果已核验 | `outcome_verified` | 指定指标在指定观察期内已有证据 |

前一行不能推出后一行。`publish_once` 票据被消费、一次点击发生、自动测试通过或本地工件存在，都不能自动提升这些 Claim。

## 3. 页面表达规则

- 入口导语先说当前对象与下一步，再补实现边界。
- 按钮使用“动作 + 对象”或清楚的动作结果，例如“创建 Agent 任务”“重新读取正文”“核验后台记录”。
- 空状态包含现状、可执行下一步与安全边界；没有可执行动作时说明需要什么条件。
- 错误提示包含失败对象、保留了什么、下一步怎样恢复；技术错误码放在详情或括号中。
- 状态文案描述已经观察到的事实，不用虚构百分比、模拟进度或乐观完成词。
- 同一边界只在最需要的位置完整解释；相邻卡片不反复用“不是……而是……”重讲系统规则。
- `Build`、`Release`、`PlatformTarget`、`Revision`、`WorkingCopy`、`Composition`、`D1`、`SHA-256`、`CAS`、`MCP` 等稳定对象可以保留。面向普通用户第一次出现时采用“英文（中文用途）”，例如 `Build（构建工件）`、`Release（发行记录）`；按钮可直接使用清楚的中文动作。代码、命令、路径、URL、对象 ID 和机器字段保持原样。
- 普通视图先显示人能采取的动作；原始 JSON、枚举、对象 ID 与完整技术事件后置到“技术详情”。

## 4. 已知事故回归

- 不把“Agent 任务已创建”写成“Agent 任务已发布”，避免与内容公开发布混淆。
- 不把“视频发布流程已走完”写成效果完成；只能在四层证据齐全时写“视频发布证据链已闭环”，并继续说明不等于效果已核验。
- 不用“这里不是日志仓库”作为证据页的主说明；直接告诉用户可以检查哪些状态、缺什么证据、下一步做什么。
- 不把索引存在、能力入口可找到、任务 `done`、工件已创建或票据已消费写成更高层完成结果。
- 不在同一页面重复解释 Primary、分支和发行镜像；首次说清作用，后续只显示当前状态。

## 5. 验收

1. 运行 `scripts/export-interface-copy.mjs`，保存按文件和行号绑定的全站中文语料。
2. 对纯文本语料运行自然中文扫描。扫描只定位候选；所有 high、medium 与抽样 low 都须结合页面位置人工裁决。
3. 冷读每个主要工作面，检查标题、导语、主要动作、空状态、错误与恢复提示是否能回答本合同第 1 节的四个问题。
4. 运行受影响的合同测试、完整构建与 lint；错误码、状态枚举、权限和证据 Claim 不得漂移。
5. 在桌面与窄屏真实页面检查换行、按钮名称、可访问名称、空状态和技术详情；源码通过不等于页面可读。

自动扫描零命中、构建通过或截图存在，都不能单独证明全站表达已经完成；最终结论由主协调者结合源码、合同、测试和真实页面读回给出。
