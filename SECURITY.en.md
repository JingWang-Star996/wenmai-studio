# Security Policy

## Supported scope

Security fixes target the current code on the repository's default branch. Please update to the latest version and report issues with the smallest reproducible scope.

## Private reporting

Do not disclose vulnerabilities, credentials, access tokens, private addresses, personal data, or exploitable details in public issues, discussions, commits, or logs.

For a potential vulnerability, use private vulnerability reporting from the repository's **Security** page on GitHub. A private reporting channel is not hard-coded to a personal email address in this repository. If that feature is not enabled, contact a repository maintainer to establish a controlled private channel before sharing details.

Reports should include, where possible: the affected version or commit, impact, minimal reproduction steps, necessary sanitized evidence, and your proposed disclosure timeline. Do not attach real credentials or access tokens.

## Handling and disclosure

Maintainers will acknowledge the report, assess impact, and communicate remediation progress within a reasonable scope. Please avoid public technical details until a fix is released or a disclosure date is mutually agreed. We may ask for help validating a fix, but will not ask for real credentials.

## Scope

Limit reports to code and configuration in this repository. Third-party services, deployment environments, or account configuration may need to be handled by their respective maintainers.
