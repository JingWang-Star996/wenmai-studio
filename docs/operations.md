# 运维、备份与迁移

[English](operations.en.md) · [首页](../README.md)

## 运行检查

使用 `npm ci` 安装锁定依赖，使用 `npm run dev` 开发，使用 `npm run build` 后 `npm run start` 验证构建。服务固定为 `http://[::1]:3000`；不要把它改成公开监听地址来规避接入问题。

运行前确认本机 D1 `DB` binding 可用。Provider、浏览器会话和平台连接均需独立检查；默认不连接平台。不要在日志、仓库或备份名中写入密钥。

## 备份

备份至少包括：数据库导出或可恢复副本、对应迁移、应用版本/提交标识，以及必要的导入工件和其摘要。将备份保存到受保护位置，定期在隔离副本上验证可读性和恢复步骤。备份成功不表示恢复成功，必须有恢复演练证据。

## 迁移与恢复

1. 停止写入或为当前状态建立一致快照。
2. 复制目标数据库，先在副本运行迁移。
3. 记录迁移前后版本、输入摘要、命令和结果；运行相称测试。
4. 只有副本验收后才对目标执行，并保留回退副本。
5. 失败或结果不明时停止写入，保留证据并从已知良好副本恢复；不要自动重复高影响步骤。

迁移脚本或 schema 改动需要代码所有者的审查；本文档不授权数据库删除、不可逆迁移或外部发布。

## 故障处理

- **无法打开应用**：确认依赖已安装、开发命令仍在运行，并使用固定 origin。
- **D1 binding 缺失**：检查本机运行配置；不要以伪造 binding 或远端数据库替代。
- **模型调用失败**：记录 Provider、动作、摘要和错误；路由合同不保证服务可用，先回到确定性或协调者流程。
- **提交结果不明**：冻结该发布写操作，先做只读目标探测，不重复点击。

## 维护验证

先运行受影响领域的 `test:*` 脚本，再运行 `npm run lint`、`npm run build` 或 `npm test` 中与风险相称的组合。测试和本机读回不等同于外部平台已接受或公开可见。
